# Dashboard

- `src/app/(authenticated)/page.tsx` is a server component around the client `dashboard-page.tsx`. **On a document request** (`isDocumentRequest`, `src/lib/document-request.ts`: `Sec-Fetch-Dest: document`, else `Accept: text/html` — never `headers().get("rsc")`, which Next strips) it runs `loadDashboardSeed` (`src/lib/dashboard/load-dashboard-seed.ts`): the routes' own GET handlers for stats, sparklines, Recently Added, lifecycle summary, schedule info, sync status and servers, under one `withSharedSession`, each within `DASHBOARD_SEED_BUDGET_MS` (1.5 s; late or failed reads are left to the zone). Database reads only. URLs are built once in `src/lib/dashboard/seed-urls.ts` for both sides. Zones take their answer through `useDashboardSeed(url)` (`src/components/dashboard/dashboard-seed.tsx`), handed out once (`DashboardSeedProvider` marks it consumed). Client navigations and prefetches get no seed.
- **The server HTML and the hydrating render must write identical text** (otherwise React rebuilds the page, #418): format time-relative text against `useRenderNow()` (`formatRelativeDate`/`formatUntil`/`formatSyncEta` take a `now`), counts through `useCountFormat()`, and the greeting/date through `useServerClock()` (`serverClock()` from the page). Recently Added and the Insights grid render only after hydration (the grid inside a `startTransition`); zones are `memo`'d. `resyncIfEventsSince(seed.at)` covers events emitted before the stream connected. `e2e/dashboard-server-render.spec.ts` covers this.
- **The page owns its stats**: fetched on load (unless seeded), on a server pick, on `sync:completed` and on `FIGURE_EVENTS` (`sync:failed`, `server:changed`, `watch-history:updated`), and at most every 10 s while a sync runs (`LIVE_STATS_INTERVAL_MS`, through the indicator's `onSyncActive`). The current server filter is read through a ref; the saved layout is read only once (a re-read could revert an in-flight save). Lifecycle events refresh only the schedule info.
- Zones render at once and apply each response as it lands: the status strip, lifecycle zone and Recently Added mount immediately; library tiles mount once types are known (`stats: null` allowed); the Insights grid waits for `layoutSettled`/`typesSettled`. "Failed to load dashboard" shows only when the LATEST stats request failed and no stats are on screen (`statsFailed`).
- Servers come from `useServers`, types from `useLibraryTypes`. Sparklines come from one `GET /api/media/stats/sparklines?types=…&serverId=` through the `timeline:` cache (`getTimelineCached`). The sync indicator and status strip share `/api/sync/status` via `fetchSyncStatus` (`src/lib/sync/sync-status-client.ts`).
- **Custom cards** load through `customCardBatcher` (`src/lib/dashboard/custom-card-data.ts`) → one `POST /api/media/stats/custom-batch` per synchronous turn (≤ `CUSTOM_CARD_BATCH_LIMIT` 50, repeats sent once), each answered by its own route's GET as `{ status, body }`, six at a time under `withSharedSession`; one card's failure fails only that card.
- `computeDeletionStats(userId)` (`src/lib/lifecycle/deletion-stats.ts`) backs `GET /api/lifecycle/stats` and `GET /api/lifecycle/summary` (exactly the pipeline zone's figures). It drops matches with a PENDING delete in SQL, takes sizes from one `id = ANY($1)` lookup, and deliberately does not sum member sizes in one correlated statement (see JIT under "Prisma and Database" in CLAUDE.md).

- **Insights cards are never re-created by the editor**: `DashboardCardGrid` renders each card's content once, through a portal, into a per-card host node (`CardHosts`, class `CARD_HOST_CLASS`); the plain cell and the editor's frame only hold that node (`CardSlot`), so Customize/Done keep every card's state and data. Content is a memoised `CardBody` redrawn only when the shared context or the card's own `config`/`display` changes (`sameCardDisplay`) — not on moves, resizes, drag markers or unrelated page state. The page resolves the layout in a `useMemo` and its editing callbacks read the latest layout from `layoutRef`, so they stay stable; keep both, or every chart redraws on every page update.
- **Per-card display choices** (`src/lib/dashboard/card-display.ts`): `CardEntry.display` holds a breakdown card's view, Top N, type pick and hidden values, and a custom card's type pick and hidden values, saved with the layout (validated by `isValidCardDisplay` in `isValidLayout`, loaded leniently by `normalizeCardDisplay`; defaults are not stored). Cards read and write them through `useDashboardCardDisplay` (`src/hooks/`); without `onChange` (the custom-card dialog's preview) the choices are local. Changing the Insights type filter clears every card's type pick in one save (`clearTypePicks`).
- **Editor actions**: Remove and Reset each toast an Undo (`handleCardRemove`, `handleResetLayout`); the size handles are focusable separators moved by the keyboard (`widthForKey`/`heightForKey`, `src/lib/dashboard/resize-keys.ts`); a set height applies only from `md` up (`dashboardCardStyle`).
- **Insights layout editor** (`sortable-card-grid.tsx`, loaded only in edit mode; `sortable-card.tsx`): the grid holds still while a card is dragged (`holdInPlace` strategy, `DragOverlay` label) and the drop target is the card nearest the pointer within its row, before/after by which half (`pickDropTarget`, `moveCard` in `src/lib/dashboard/card-drop.ts`; the keyboard steps through `adjacentCardId`). Resize handles sit in the grid gap, outside the card. **A card never paints outside its cell**: the card's host node carries `.dashboard-cell` (`globals.css`) — a size container whose direct `Card` clips and whose `CardContent` scrolls; a card whose root is not a `Card` (`TopPlayed`) scrolls itself. Lay card content out by the card's width (`@sm:`, `@sm/card-header:`), not the window's. `e2e/dashboard-layout-editor.spec.ts` covers both.

## `src/lib/dashboard/`

- `src/lib/dashboard/` — pure dashboard logic, unit-tested: `card-registry.ts`; `server-selection.ts` (`selectableServers` drops disabled servers, `reconcileSelectedServer`, `dashboardStatsUrl`, `reconcileSelectedType`); `card-drop.ts` (drop targeting and reordering for the layout editor); `card-display.ts` (per-card display choices); `card-label.ts` (a card's name); `resize-keys.ts` (keyboard resizing); `sparkline.ts` (`buildSparkPoints` — 12 months ending at the current month); `pipeline.ts` (`pipelineStateFrom`); `custom-dimensions.ts` (`supportsTimelineBreakdown` — only direct/value_map/numeric_bucket, the timeline route 400s on the rest; `canCrossTabulate` — never two stream dimensions; `isSubmittableCustomCard`; `breakdownValueLabel`; `customCardTitle` — a custom card's title, shared by the card and the drag label). A dimension's `excludeTypes` is applied by `computeBreakdown`, `computeCrossTab` and the timeline breakdown (`excludedTypesSql`); cross-tab date buckets are UTC and stream dimensions count per item (`SELECT DISTINCT mi.id`, `MAX_ROWS_PER_TYPE`); `computeTimeline` gap-fills at most 5,000 buckets.
