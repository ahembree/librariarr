# Rule engine

Detection, scheduling and execution (including the evaluability guard) are in the `lifecycle` skill.

- Rules are recursive `ConditionGroup`s (`src/lib/conditions/types.ts`) with AND/OR, stored as JSON in `RuleSet`. Rules and groups support `negate`; group negation is pushed down to rules before evaluation (`pushDownGroupNegation`, `src/lib/conditions/negation.ts`) so both phases share NULL semantics. A negated stream query flips `any` ↔ `none`; a negated `all` (stream-query rules are always ANDed) becomes a plain OR of single-rule `any` stream queries, each rule's `negate` flipped — NOT all(P) is "some stream of the type fails P", and an item with no stream of the type matches neither. Never drop a NOT.
- **Legacy flat rule sets** are converted by `src/lib/rules/legacy.ts` (pure, client-safe): `legacyRulesToGroups` (engine; enabled rules only — a rule's `condition` connects to the NEXT rule: buckets split after each enabled AND rule, OR within, AND between) and `legacyRulesToEditorGroups` (editor; same buckets, disabled rules kept in place). Only enabled rules place bucket boundaries.
- **Two-phase evaluation**: Phase 1 converts rules to Prisma WHERE; Phase 2 post-filters in memory (Arr/Seerr metadata, stream aggregation, wildcards, array fields). Engines load only what a rule set reads: the three lifecycle engines (`evaluateLifecycleRules`, `evaluateSeriesScope`, `evaluateMusicScope`) load candidates with `omit: UNREAD_ITEM_COLUMNS` (cast/crew, tagline, original title, file path, playback bookkeeping), and streams only for a stream rule (`hasStreamRules`). Stream query groups' Phase 2 is `evaluateStreamQueryGroupInMemory` (`src/lib/conditions/stream-query-eval.ts`); every "lowest id" pick uses `compareIds` (`compare-ids.ts`).
- **The lifecycle engine (`src/lib/rules/lifecycle-engine.ts`) and the query engine (`src/lib/query/query-engine.ts`) share one implementation of both phases — fix operator/NULL semantics once, in the shared functions**:
  - Phase 1: the single `ruleToWhere` dispatcher in `src/lib/conditions/where-builder.ts` (both pass it to `buildGroupConditions`).
  - Phase 2 Arr/Seerr: `evaluateArrRule`/`evaluateSeerrRule` exported from `lifecycle-engine.ts` (`query/arr-filter.ts`, `query/seerr-filter.ts` are re-export shims).
  - JSON-array fields (`genre`, `labels`, `country`) are evaluated **only** in Phase 2 through `matchArrayField` (`src/lib/conditions/array-field-eval.ts`), **case-insensitive** for every operator, `[]` = empty. `genreLabelsHandler` returns `{}` and `hasArrayFieldRules` forces Phase 2, like `resolution`.
  - `hasExternalId` through `matchExternalIdField` (`external-id-eval.ts`); the NAME-LIST fields `arrTag`, `seerrRequestedBy`, `watchedByUser`, `matchedByRuleSet` through `matchNameListField` (`name-list-eval.ts`).
  - The `match*Field` evaluators (`matchArrayField`, `matchExternalIdField`, `matchNameListField`) return `boolean | null`: `null` = unknown operator, and the caller must then match nothing **without** applying `negate` (a `default: false` through `negate` fails open to match-all). `evaluateArrRule`/`evaluateSeerrRule` return `boolean` with `negate` already applied (a dead rule returns `false` before it).
  - `watchedByUser` also has a Phase-1 clause (`watchHistory: { some|none }`): every value it hands an insensitive `equals` goes through `escapeLike` (that compiles to `ILIKE`); its `in` form compiles to `LOWER(col) IN (…)` and must NOT be escaped.
- **Stream language fields** (`audioLanguage`, `subtitleLanguage`) are fail-closed on absent data: an item with no KNOWN language of that type (none, `""`, `Unknown`) matches no comparison operator, positive or negative, and `negate` does not flip that. Phase 1 ANDs a "has a known language of this type" conjunct onto the **finished** clause, after `applyNegate`, for `equals`/`contains`/`notEquals`/`notContains` (not `isNull`/`isNotNull`); Phase 2 bypasses `negate` there. Codec fields (`streamAudioCodec`) keep plain semantics.
- File size rules: user input in MB, converted to bytes for queries.
- **Series-aggregate fields** (`episodeCount`, `watchedEpisodePercentage`, …) are evaluated only against an aggregated series record. A SERIES rule using one goes through the aggregate path (`evaluateSeriesScope` / `aggregateSeriesAndFilter`) **regardless of `seriesScope`** — `hasSeriesAggregateRules` is part of the Phase-1 gate in both engines (`where-builder` returns `{}` for them). Preview and diff route `seriesScope=false` + an aggregate field through `evaluateSeriesScope(…, true)`, as detection and test-item do. That run is per episode: a show is a match iff at least one episode passes on its own with the series aggregates injected as constants (`episodesMatchingIndividually`, `series-aggregates.ts`), and its members are exactly those episodes — the show's aggregate record is **no gate** (it read per-episode fields off the representative). The query engine's aggregate path (`computeAggregateSurvivingEpisodeIds`) selects through the same helper in both views — the grouped view lists a show's matched episodes, and the query-actions route's grouped re-run in episode view resolves the same members. A show that passes only as a whole is not a match there. In this per-episode selection only the aggregates, Arr and Seerr fields are constant across a show's episodes (`readsEpisodeValues`); title, play count, size, streams, watchers, cross-system values and external ids are the episode's own — deliberately unlike group scope below, since series scope off asks about episodes. Test Media evaluates the tested episode the same way (no show-level gate).
- **A criterion whose value belongs to one episode or track may never make a whole show or artist an action's target** (`src/lib/conditions/group-scope.ts`, client-safe and alias-free — the docs' rule-set library check imports it). Two judgements, each with its own blocked list per library type (`isBlockedAtGroupScope(field, type, judgement)`, `findGroupScopeBlockedCriteria(rules, type, judgement)`; enabled or disabled rules at any depth; any `sq*` field and stream query group always blocked):
  - **group** — series scope on (SERIES) / artist scope on (MUSIC): `GROUP_SCOPE_BLOCKED_FIELDS[type]` = every field whose value is one file's or one item's (video, audio, `container`, `duration`, the stream fields, `year`, `originallyAvailableAt`, `rating`, `audienceRating`, `ratingCount`, `albumTitle`) plus the content metadata the sync stores per episode/track without keeping a show's or artist's members alike (`genre` — an episode keeps its own and takes the show's only when empty, a track has no artist fallback; `studio`/`contentRating` — each item's own on Plex, `Studios[0]`/`OfficialRating` on Jellyfin/Emby; `labels`/`country` — each item's own Plex tags; `isWatchlisted` — Jellyfin/Emby per-item favourite, Plex per item and never set by the incremental sync), and on MUSIC `hasExternalId` (a track carries its own recording id; a show's episodes all store the show's ids). Allowed: the group values (`isGroupValueField` minus the stream fields), Arr, Seerr, the series aggregates.
  - **member** — the scope off with an armed action that acts on the whole Sonarr series / Lidarr artist (`wholeRecordActionOf`: `WHOLE_RECORD_ACTION_TYPES[type]` — Delete from Sonarr/Lidarr, Unmonitor/Monitor & Delete Files (they unmonitor/monitor the record), Change Quality Profile, Lidarr's Unmonitor Only and Search for New Copy — plus Arr tags on any action and Lidarr's Delete Files with search after): every field but those each member answers alike (`parentTitle`, a SERIES `hasExternalId`, the series aggregates, Arr, Seerr). Sonarr's Delete Files (search by episode id), Unmonitor/Search with series scope off (episode-scoped) and Do Nothing without tags act on the matched members only. `actionEnabled: false` or nothing configured is not armed; absent (a scheduled action's snapshot) is.
  - `groupScopeViolation(type, seriesScope, rules, action?)` is the one predicate (`judgement`, `wholeRecordAction`, `scopeOnResolves`): `ruleSetCreateSchema` refines on it (scope on and action off unless the body says otherwise; a member violation's issue is on `actionType`); the rule set PUT checks the merged state through `ruleSetScopeError` whenever the body carries `rules`, `seriesScope`, `actionType`, `actionEnabled`, Arr tags or `searchAfterAction` — an action-only body (`actionCausedOnly`) is refused only for a member violation, so turning off or fixing an already-invalid rule set's action stays allowed; `checkLifecycleRuleEvaluability` skips on it (sixth argument the scope, seventh the action — the detection paths pass it; preview/test-item/diff pass none and judge the scope only); `actionHoldOf`/`actionHoldFor` hold on it (lifecycle skill); `evaluateSeriesScope` (scope on only) and `evaluateMusicScope` refuse a group violation as defence in depth (log + `[]`); the rule editor gates criteria and actions on it; convert-to-rule turns the scope off for a group violation (`convertedScope`) and never arms an action (`convertedWholeRecordLimit` names what keeps a whole-record action off). `wholeRecordActionBlockedBy` is the picker's per-action check. `tests/unit/conditions/group-scope.test.ts` classifies every `CONDITION_FIELDS` entry per type for both judgements with the reason, and every Series/Music action type, so a new field or action must be placed.
- **A group (show, artist) matches through its members.** In series/artist scope a group matches iff at least one member satisfies the WHOLE rule, each member seen as the group record carrying that member's own per-member values (`matchGroupThroughMembers` in `series-aggregates.ts`, wrapped by `evaluateGroupThroughMembers` in `lifecycle-engine.ts`; used by `evaluateSeriesScope`, `evaluateMusicScope` and Test Media). Group values stay constant across members (`isGroupValueField`): name (`title`/`parentTitle`), `playCount` (total), `fileSize` (sum), `lastPlayedAt` (latest), `addedAt` (earliest), `watchedByUser` (union), stream fields and stream queries (stream union), cross-system (folded), `hasExternalId` (the group's ids), series aggregates, Arr, Seerr. Every other condition field is per member (`MEMBER_VALUE_COLUMNS`; `tests/unit/conditions/series-aggregates.test.ts` pins the split, so a new field must be placed) — and every per-member field is blocked at group scope (the group-scope test pins it), so a rule set the gate admits reads no per-member value and each group is evaluated once (`readsMemberValues` / `hasMemberValueRules`, decided once per run). Members are tried lowest id first (`compareIds`).
- **Reporting a group match** shows what it was selected on: the engines return the group (same `id` = representative, same group snapshot shape) carrying the first passing member's per-member values (`memberValuesOf`), so the stored `itemData`, `getMatchedCriteriaForItems` and `getActualValuesForAllRules` name that member's value. A per-episode selection (above) is stored as the show but reported from the first passing episode's own evaluation record, attached non-enumerably with `withEvaluatedRecord` (never spread or stored; `asEvaluated` reads it via `evaluatedRecordOf`). Reporting looks Arr/Seerr up by the match record's own external ids and keys results by its `id`. Identity is unaffected: `title`, `parentTitle` and `externalIds` are group values and `matchIdentityChange` compares a group's year only for movies.
- **Group records** (a show rolled up from its episodes, an artist from its tracks) are stored and returned as the group — `title` = the show/artist, `parentTitle` cleared — the snapshot shape `matchIdentityChange`, `isGroupSnapshot` and the action title snapshot rely on. Evaluation reads the name as `parentTitle` ("Artist / Series") through `withGroupParentTitle` (`src/lib/conditions/series-aggregates.ts`): in `evaluateSeriesScope`, `evaluateMusicScope`, `serializeSeriesAggregateForEval`, Test Media's group, and the matched-criteria/actual-value reporting (`asEvaluated` in `lifecycle-engine.ts`, recognised by `isGroupRecord`). Never evaluate a group with a NULL `parentTitle`: its negations match every show.
- **Cross-system fields** (`matchedByRuleSet`, `hasPendingAction`, `serverCount`) come from `fetchCrossSystemData(ids, { excludeRuleSetId })` and are enriched on every path: the series- and artist-scope engines and test-item's group fold them across a group's members with `foldCrossSystemData` (matched by any, pending if any, highest server count), and the aggregate engines and the Query table carry the folded values; a per-episode selection (series scope off forced through the series path, the query engine's aggregate and grouped paths) reads each episode's own. A grouped match's `itemData.memberIds` all count as matched (member lists intersected in JS — a SQL join of them hits JIT). **Has Pending Action** counts an action stored against the item, naming it in `matchedMediaItemIds`, or naming another copy (`copyIds` or same `dedupKey`), excluding **the evaluating rule set's own** actions (`excludeRuleSetId`, passed by detection, the diff, the preview and Test Media) so a rule set never cancels and reschedules its own action. The server-count `groupBy` goes out in 10,000-key slices (`inChunks`). The flat engine returns rows with the values on them so a match records them among its matched criteria.

## Query table criterion columns

Every condition field can be a column in the Query page's table. `src/lib/query/column-fields.ts` (client-safe) derives the list from `CONDITION_FIELDS` minus fixed columns (`BUILTIN_COLUMN_FIELDS`). Values are fetched on demand by `POST /api/query/column-values` (`computeQueryColumnValues`, `src/lib/query/column-values.ts`) for the rows on screen and visible columns only, in the table view only. `ColumnValueLoader` (`src/lib/query/column-value-loader.ts`, wrapped by `useQueryColumnValues`) splits requests at `MAX_COLUMN_VALUE_ITEMS` (50,000) and drops answers for a result set that is no longer the latest. Scoped to enabled servers and the run's selection; a grouped series row is answered from its per-library aggregate (stream counts read null); Arr reads the run's selected instance, Seerr every enabled one; an unavailable source yields null plus a `warnings` entry. `tests/unit/query/column-values.test.ts` requires every condition field to be a fixed column or a criterion column, and every criterion column to be listed in `isColumnFieldHandled` (the fields `columnValueOf` answers).
