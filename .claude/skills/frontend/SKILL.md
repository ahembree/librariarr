# Frontend patterns

The dashboard has its own skill (`dashboard`); realtime subscriptions and fallback polls are in `realtime-events`. UI styling rules are in CLAUDE.md "Styling" and the style guide (`docs/src/content/docs/docs/development/style-guide.mdx`).

## Settings page (`/settings`)

- `page.tsx` holds the state and handlers; the 8 tabs in `settings/tabs/` render from props. Exception: the Integrations tab keeps its own form state through one `useIntegrationInstances(behavior, { instances, refresh })` per type (`settings/use-integration-instances.ts`; pure helpers `changesConnection`, `editRequestBody`, `testConnectionBody` in `settings/integration-instances.ts`) rendered by `IntegrationInstanceSection`, and stays mounted once opened (`forceMount`). Shared types in `settings/types.ts`. `MediaServerConnectionFields` is the server form both onboarding and Add Server render.
- Each tab's code loads on demand through `lazySettingsTab` (`settings/lazy-tab.tsx`), listed first in that tab's `TAB_CODE.<tab>.load`; a new tab needs a `TAB_CODE` entry. Each tab renders once its own data is in (`loadedTabs`), the open tab's requests issued first; a new fetcher goes in the list of every tab that renders its data.
- The open tab IS the URL hash, read through `useHashTab(validTabs, fallback)` (`src/hooks/use-hash-tab.ts` over `src/lib/url-hash.ts`, written with `replaceUrlHash`). Never read the hash once in a `useState` initializer — on a client-side navigation that is the previous page's hash.
- The opening reads arrive in one request: fetchers read through `bundleOf(bundleRef).get(path)` (`src/lib/settings/request-bundle.ts`), and the first read of each path in `SETTINGS_BUNDLE_PATHS` (`src/lib/settings/settings-bundle-paths.ts`) is answered by `GET /api/settings/bundle?paths=…`, which runs each route's own GET (`{ parts: { [path]: { status, body } } }`) under one session check (`withSharedSession`, `src/lib/auth/shared-session.ts`), creating the settings row first. Later reads go to the route itself. **A new bundled fetcher's GET must be callable with no arguments** (`withSession(async (session) => …)`, or an optional request) and be added to both `SETTINGS_BUNDLE_PATHS` and the bundle route's `HANDLERS`. The SSO and API-key sections' first reads are preloaded the same way (`preloadAuthSections` via `createPreloadedReads`, `settings/preloaded-reads.ts`, answered once).
- The System tab loads only when opened (`/api/system/info?updateCheck=false`, image-cache stats, changelog); its update status and dot come from `/api/system/update-check` at low priority. Without `updateCheck=false`, `/api/system/info` (and the v1 mirror) include `updateInfo`.

**What's new dialog** — `WhatsNewDialog` (`src/components/whats-new-dialog.tsx`, mounted in `AuthenticatedShell`) shows every release note newer than `AppSettings.lastSeenVersion` up to the running version (`GET /api/settings/whats-new`; `selectWhatsNew` and the release-please parser `parseReleaseSections` in `src/lib/version/release-notes.ts`; `ReleaseNoteSections` renders for both it and the System tab). It reads `fetchReleaseNotes()` (100 releases), never the 10-item changelog; `truncated` flags older notes past that page. It opens only once the running version's release is listed. Closing `PUT`s the shown version under `FOR UPDATE`, never stepping it back. Setup stores `installedVersion()`; a restore keeps the newer of the file's and the in-use value (`keepSeenReleaseNotes`).

## Library detail pages

**Library** — `/library/movies`, `/library/series` (with `/seasons` and `/episodes`), `/library/music`. Detail pages:

- All seven detail pages load through `useMediaDetailRecord(id, { mediaType, plays, integrations?, children?, playLinks?, tickOn?, refetchOnTick? })` (`src/hooks/use-media-detail-record.ts`; with `useBackOverride`, `useDetailChildren`, and `DetailPageStates`/`RatingChips`/`genreChips` in `src/components/media-detail-parts.tsx`). It calls `prefetchMediaDetail` beside the record fetch once per id (first play-history page via `mediaPlaysUrl`, `/arr-info`, `/seerr-info`, the child list) and ignores a `sync:completed` whose `libraryTypes` leave out the page's type. Artist and album pages pass `integrations: false`.
- Show, season, artist and album pages read their child list by the record's id (`?itemId=` on `series/seasons`, `series`, `music/albums`, `music`; scope resolved by `loadDetailScope` in `src/lib/api/detail-scope.ts`, 404 when not the user's or not of the list's type), so `detailChildrenUrl` starts with the record.
- **`detailPrefetch`** (`src/lib/media/detail-prefetch.ts`): a 30 s store of GET answers keyed by URL, each handed out once by `take`, errors never kept; `peek` reads without consuming (the hover popover), so the record is still there for the click. Everything that reads by id (`PlayHistory`, `IntegrationsSection`, detail pages, `MediaDetailContent`, `useMediaDetailPanel`) goes through `detailPrefetch.fetch`. Library cards (`MediaCard`'s `prefetchMediaId`) and `MediaTable` rows warm the record on intent (`intentHandlers`, `src/lib/intent-prefetch.ts`: pointer resting `INTENT_DELAY_MS` 120 ms, mouse/pen press or focus — never a touch press). Keep URL builders shared so both sides hit the same key. Records and play pages are dropped with the list cache on every media-changing event.
- **Play history**: `PlayHistory` (`src/components/play-history.tsx`) renders per-play rows (user / date-time / episode). Show and season pages render it as a full-width section over `GET /api/media/series/watch-history`. The episode page, `/library/movies/[id]` and `/library/music/track/[id]` pass it through `MediaDetailContent`'s `historySection` slot (`variant="card"`; movie and track with `mediaItemId singleItem` over `GET /api/media/[id]/plays`), which replaces the built-in per-user aggregate card and skips its live `/api/media/[id]/history` fetch (`hasHistorySection`). `MediaDetailSidePanel` fills the same slot (series identity + season/episode for an episode, its own id otherwise). `singleItem` drops the title line; `PlayRow` links out only for a SERIES row.
- `/api/media/[id]/history` (live per-user aggregate for one item, from the server) and `/api/media/[id]/plays` (stored per-play rows) are deliberate siblings, not substitutes. The two play routes share `src/lib/media/play-history.ts` (`PLAY_HISTORY_SELECT`, `serializePlayRow`, `fetchPlayHistory`, `parsePlayHistoryPaging`) and differ ONLY in how they resolve in-scope items — add columns there, never to one route. `series/watch-history` matches on `seriesKey` (prefers a `seriesKey` param; legacy `parentTitle` matched case/space-insensitively), resolves in-scope episode ids first, includes every user's plays, and does **not** apply dedup (a play belongs to the copy that was played).
- Play lists page 5 at a time (`PAGE_SIZE`) through the shared `src/components/pagination-controls.tsx` (also used by `/library/history`), **centred** (the fixed `BackToTop` button covers the right corner). Last/Next use `totalCount`, not `hasMore`; `multiServer` comes from servers seen across every loaded page in the scope.
- `detailLoaded`: the movie, episode and track pages and the side panel (`useMediaDetailPanel`'s `panelProps.detailLoaded`) already load the full `/api/media/[id]` record, so `MediaDetailContent` reads streams and credits from `item` instead of fetching again. If the panel's request fails with a seed on screen, the flag turns false and the content fetches the record itself.
- The detail hero paints the grid card's poster under the full-size one when this tab already loaded it (`posterPlaceholderFor`, `src/lib/loaded-images.ts`, fed by `FadeImage`'s `onLoad`; never on a direct visit). The side panel's 80px poster requests `CACHE_WIDTH_GRID`.

## Frontend data loading

- **List cache** (`src/lib/media/list-cache.ts`): every library page reads its list through it (`fetchListProgressively` for flat pages, `loadCachedList` for grouped; keyed by URL with sorted params). Fresh for `LIST_FRESH_MS` (60 s) while the stream is live; up to `LIST_MAX_AGE_MS` (15 min) it is shown at once and refreshed behind; at most 6 lists. `AuthenticatedShell` drops it, and the detail-prefetch records and play pages (`dropMediaDerivedPrefetches`; Arr/Seerr answers are kept), on `sync:completed`, `sync:failed`, `watch-history:updated`, `server:changed` and `settings:changed` through `beforeRealtimeEvents`. `set` takes the `generation()` read at request start, so an answer that crossed a clear is handed to the page but not stored.
- **Every library page loads its list through `useLibraryList({ url, params, mode, select?, syncScope, debounceMs? })`** (`src/hooks/use-library-list.ts`), which bundles `useListFetch` (first fetch in a microtask; later filter/sort changes debounced 300 ms, movies 0), `useLibrarySyncRefetch` (skips when `syncCompletedConcerns(event, scope)` in client-safe `src/lib/media/sync-scope.ts` shows the sync cannot have changed the view; missing meta always refetches), `useLatestRequest`, and the loading flags. Params are compared by value; `select` is read through a ref; `refetch` is what `SyncLibraryButton`'s `onSyncComplete` calls. A fetch for the params already shown is a quiet refresh (no skeleton; `{ quiet: true, shownLength }`; swapped in inside `startTransition` so keyed cards stay mounted). New params show the skeleton. A failed request keeps the list only when it answered the same params.
- Flat DB-paginated views (movies, all episodes, all tracks) load in two passes via `fetchListProgressively` (`src/lib/media/progressive-load.ts`): `FIRST_CHUNK_SIZE` (100), then `limit=0&offset=100`. Gate the header count and `useScrollRestoration` on `loadingRest`, not `loading`. Grouped views (series, artists, albums, all-seasons) stay single-request. Detail sub-views (a season's episodes, an album's tracks) fetch the whole child list with `limit=0`.
- **Poster grids** — the seven list pages, Query, Matches, Pending and the rule preview — render through `useVirtualPosterGrid` + `VirtualCardGrid` (`src/hooks/use-virtual-poster-grid.ts`, `src/components/virtual-card-grid.tsx`; `scrollElement: "main"` or `"own"`; `POSTER_ASPECT`/`SQUARE_ASPECT`/`WIDE_ASPECT`; overscan starts at one row and widens after first paint via `useDeferredOverscan`). Cells are memoised `GridCell`s, so the page's `renderItem` must be stable (`useCallback`).
- List pages share view mode, sort and filters through `useLibraryListState` (`src/hooks/use-library-list-state.ts`, view mode via `useLocalStorage`) and their empty state through `LibraryEmptyState`. A page whose filters persist starts from the restored filters and ignores re-broadcasts of identical filters (`sameFilters`, `src/lib/filters/same-filters.ts`). **Clear Filters goes through `useFilterPanelReset`** (its `resetKey` makes `MediaFilters` empty itself in place). Alphabet navigation uses the hooks' client-side `scrollToLetter`.
- **Code most pages never use loads through `lazyComponent`** (`src/components/lazy-component.tsx`, loader in `src/lib/module-loader.ts`), **never `next/dynamic`** (its Suspense fallback brings back React's 300 ms reveal throttle). Lazy today: recharts users (`CustomChartCard`, `EvidenceCard`), the dashboard's drag-and-drop `SortableCardGrid` (edit mode only; `StaticDashboardCard`s otherwise and as fallback), `RulePreviewSection`, every Settings tab, the search palette (loaded when `usePrefetchReady` says idle, or on pointer/focus through its `preload()`), the reauth dialog (`reauth-dialog.tsx`; one whose code cannot load answers false), What's new, the add-card menu, the custom card dialog and the Seerr drill-down. `MediaFilters` fetches `/api/media/distinct-values` only once its panel is about to open, is open, or a filter is set. Sidebar badges fetch at `priority: "low"`.
- **No `loading.tsx` under `(authenticated)/`** (`tests/unit/app/no-route-loading.test.ts`): pages render their own skeletons. Sidebar, `LibraryTabs` and dashboard links use full `prefetch` through `DeferredPrefetchLink` / `usePrefetchReady` (`src/components/deferred-prefetch-link.tsx`): prefetching starts after `load` (waited for at most 5 s) and the browser is idle.
- `useIsMobile`'s server snapshot is the layout's user-agent guess (`isLikelyPhone`, `src/lib/device.ts`, via `MobileGuessProvider`).

## Shell settings

- `src/lib/settings/shell-settings.ts` — `loadShellSettings(userId)` reads, in one query selecting only these fields (the row also holds credentials), the accent (a removed preset reads as `default`), the user chip's name and sign-in method (`authMethodLabel`), chip colours, table column and card display preferences, the dashboard layout, the two revisions below and `whatsNewDue`, plus in parallel the library types (`loadLibraryTypes`, `src/lib/media/library-types.ts`) and `maintenanceActive`. It and `getRequestSession` are wrapped in React `cache()`. `GET /api/settings/shell` serves the same read.
- The authenticated layout seeds `ShellSettingsProvider` (`src/components/shell-settings-provider.tsx`); the client copy is `createShellSettingsStore` (`shell-settings-store.ts`). The layout renders only on full page loads, so the store must follow saves made elsewhere: **every route that saves one of these values calls `announceDisplaySettingsChanged`** (`display-settings-events.ts`) — including `change-password` (rename), `plex/link`, `sso/link` POST/DELETE and `sso/revert` — → `display-settings:changed` → `store.refresh()` (also on reconnect resync and a tab returning after ≥ 60 s hidden). Readers use `useShellSnapshot()`; `useShellSettings()` is the store for saving. `null` from the hooks (outside the shell, or the read failed) means each reader fetches and saves on its own.
- **Dashboard layout and column preferences save with a revision** (`AppSettings.dashboardLayoutRevision`/`columnPreferencesRevision`): the PUT carries the held revision and the route answers 409 `stale_revision` via a conditional `updateMany`; a PUT without `revision` is unconditional. The store applies saves at once, queues them one at a time (each with the revision the previous returned), debounces columns 500 ms per type, refuses saves queued behind a 409, then refreshes; a refresh waits for pending saves and drops answers that crossed a local change. A refresh bringing another accent dispatches `accent-color-changed`. Card display preferences keep `localStorage` first; chip colours are saved by their callers. The dashboard never requests `/api/settings/dashboard-layout`.
- `useLibraryTypes` (`src/hooks/use-library-types.ts`) is a `createRealtimeResource` over `/api/media/library-types` (stale on `server:changed` and `sync:completed`), seeded from the layout's copy. The dashboard uses that copy only on the render that hydrates the server HTML; on later visits it reads the store, re-reading unless `isRealtimeLive() && !libraryTypesResource.needsRefresh()`.

## Component Patterns

- `src/components/ui/` — shadcn/ui primitives ("new-york"); do not edit directly.
- Custom components: `authenticated-shell.tsx` (sidebar, mobile glass header + drawer, global maintenance banner), `sidebar.tsx`, `media-table.tsx`, `media-filters.tsx`, `media-detail-panel.tsx`, `rule-builder.tsx`, `quality-chart.tsx`, `theme-provider.tsx`, `dashboard/` (fixed zones `status-strip.tsx`, `library-tiles.tsx`, `lifecycle-pipeline.tsx`; the customizable Insights grid via `dashboard-card-grid.tsx` + `card-registry.ts`).
- **Use the shared primitives rather than writing the pattern again**: `PageHeader` (`page-header.tsx` — the page `<h1>` in the required style; `icon`/`meta`/`description`, `actions` that wrap on a phone, `actionsInline`); `ConfirmDialog` (`confirm-dialog.tsx` — `destructive`, `pending`; an `onConfirm` returning a promise keeps it open and spinning; resolving `false` or rejecting keeps it open); `LoadingButton`; `InlineError` (`multiline`); `ConnectionTestResult` (`banner`/`badge`, `connectionTestLabel`); `UserAvatar` (`src/lib/avatar.ts`); `DayOfWeekPicker` (`type="button"` toggles by `Date.getDay()` index) with `formatScheduleWindow` (`src/lib/schedule-format.ts`); `pagination-controls.tsx`.
- `src/lib/format.ts`: `formatDateTime`, `formatWatchedAt`, `formatSyncEta`, `formatChannels(n, { verbose })`, `formatRelativeDate(date, { largestUnit })`, `localDateString`, `toDatetimeLocalValue`, `formatDateOnly` — reach for these before formatting a date inline.
- **Hover popovers** (`MediaHoverPopover`) always receive the same universal field set regardless of page or view, built with the `src/lib/media/hover-data.ts` builders (`hoverDataFromListItem`, `hoverDataFromSeriesGroup`, `hoverDataFromSeason`, `hoverDataFromArtistGroup`, `hoverDataFromAlbum`, `hoverDataFromRecord`); table and card views on a page pass identical fields. `summary` is the one async field: where a list omits it, pass `summaryUrl` (`hoverSummaryUrl(id)`), fetched on open through `detailPrefetch.peek`. `LazyMediaHoverPopover` serves the dashboard's top-played lists. Rules in the style guide's "Hover Popovers".
- **Quality chips and bars** come from `src/lib/media/quality-chips.ts` (`qualityChips`, the `*ChipLabel` helpers, `orderedQualityCounts`/`orderedAudioCodecCounts`, `qualitySegments`), drawn by `QualityChip`/`QualityChips` (`src/components/quality-chips.tsx`) and `QualityBar` (`media-card.tsx`). A missing value is no chip (a table's plain `-`), SDR is shown, codecs are upper-cased, counts are canonically ordered. Style guide "Quality Chips".
- **Chips vs badges**: every value, status, label, tag or criterion is a `ColorChip` (`src/components/color-chip.tsx`, rounded-rect; it takes no ref, so under `TooltipTrigger asChild` wrap it in `<span className="inline-flex">`). A shadcn `Badge` (rounded-full) is only a bare count on a control or heading, or a filter trigger's selection summary. Style guide "Chips vs Badges".
- **Transcode vs direct**: `streamDecision({ isTranscode, videoDecision, audioDecision })` (`src/lib/media/stream-decision.ts`) — any re-encode (audio-only included) is Transcode, `copy` is Direct Stream, anything else Direct Play, `null` when unknown; colours from `decisionChipClass(kind)`.
- `data-table.tsx` (`DataTable`): headers never narrower than their title (`resolveColumnWidth`); a drawn horizontal scrollbar stuck to the viewport bottom (`src/lib/scroll-thumb.ts`); opt-in `pinning` (`{ storageKey, defaultPinned }`, `src/lib/table-pinning.ts`, column `alwaysPinned`) — pins past `MAX_PINNED_SHARE` (60%) of the visible width are suspended and named in a note above the table; pin buttons hide until hover only under `@media (hover: hover)`. Layout work keys on a column-shape signature (`columnShapeKey`/`parseColumnShapes`), client sort on the sort column's own `sortValue`. The Query page pins Type/Title/Year by default.
- **Every page that opens `MediaDetailSidePanel` uses `useMediaDetailPanel`** (`src/hooks/use-media-detail-panel.ts`): one remembered width (`media-detail-panel-width`), the selection, and the load of the current `/api/media/[id]` record (a `seed` row shows meanwhile; slower earlier responses are dropped), with `prefetchMediaDetail` on `open()`. A grouped row is described with `DetailPanelGroup` (`src/lib/media/detail-panel-item.ts`: `groupOfRow`, `buildDetailPanelItem` lays group title/count/size/plays over the representative record, `detailPanelUrl` is the only "Open full page" rule). The Stream Manager resolves a session's item through `GET /api/media/by-rating-key` (exactly one match or 404) and shows `SessionStreamDetails` in `contextSection`. Matches passes the rule set's `rules` for the Logic Preview.
- **Hooks** (`src/hooks/`):
  - `useVirtualGridAlphabet` / `useTableAlphabet` (grid vs table, not interchangeable; `scrollToLetter`, `activeLetter`, `availableLetters`), `useScrollRestoration`, `useCardSize`, `useColumnResize`, `useIsMobile`.
  - `createRealtimeResource` / `useRealtimeResource` (`use-realtime-resource.ts`) — one route's answer held for the tab; its `events` mark it stale through `beforeRealtimeEvents` even with no reader; a mounting reader re-reads when missing, stale, or older than `TRUST_WITHOUT_STREAM_MS` (10 s) while not live; `seed` takes a value read elsewhere. `useServers` (`/api/servers?fields=basic` + the page's `selectedServerId`, re-read on `server:changed`) and `useLibraryTypes` are built on it.
  - `useApiResource(url, { select?, realtime? })` — `GET url` as state; prefer it for a new page's reads. `useLatestRequest()` (`begin()`/`isCurrent(token)`/`cancel()`) instead of a hand-written `reqToken` ref.
  - `useRealtimeRefetch(eventTypes, refetch)` — re-read for a run the page started: `begin()` before the request, `settle({ expectEvent, isOwn })` after; the direct re-read is skipped only when the request's own event arrived (within `OWN_EVENT_GRACE_MS`, 1.5 s) and the stream is live.
  - `useSetState`, `useStoredSet(key, defaults)` (over `useLocalStorageJSON`); `useHashTab`, `useHydrated`; `useCronScheduleSetting({ endpoint, bodyKey, … })` (one Settings → Scheduling schedule).
  - `useRuleEditorData()` — the rule editor's tab-independent data, loaded once by `/lifecycle/rules` and passed to each tab's `LifecycleRulePage` as `data`; dialogs in `lifecycle-rule-dialogs.tsx`.
  - `useLifecycleExceptions({ announce? })` (excepted ids via `?idsOnly=1`, exclude POST, `ExcludeReasonDialog`); `useRuleSetTypeFilter` and `RuleSetGroupCard` for Matches/Pending.
  - `use-live-session-count.ts` — the Stream Manager publishes its count (`publishLiveSessionCount`) and the sidebar badge uses it instead of reading `/api/tools/sessions`.
  - Plus `useLibraryList`, `useLibraryListState`, `useLibrarySyncRefetch`, `useFilterPanelReset`, `useVirtualPosterGrid`, `useMediaDetailRecord`, `useBackOverride`, `useDetailChildren`, `useFallbackPoll` (above).

## Naming series and episodes

An episode row's `title` is the episode's name; the show is `parentTitle`. Name TV items through `src/lib/media/display-title.ts` (client-safe):

- a **show** → `seriesTitleOf`;
- **one episode** → `formatEpisodeTitle` → `"<Show> SxxExx"` (unnumbered: `"<Show> — <episode title>"`), or `formatMediaItemTitle` for a row of any type; `formatEpisodeCode` is the bare `S01E02`. The episode's own title is fine only where the show is already on screen or as secondary detail.
- **lifecycle actions** → `actionTargetTitle` (`src/lib/lifecycle/action-target.ts`): named by the show, `"<Show> SxxExx"` only when the action acts on exactly one episode. That episode need not be the representative, so callers pass the members' rows as `memberEpisodes` (`loadMemberEpisodes` in `member-episodes.ts`, or rows `loadGroupMemberStats` already loaded). Used by the executor's logs and Discord summaries, `executeActionsForItems`, force-retry and the Pending rows (`buildActionMediaItem`); the name goes to `executeAction` as `targetTitle`. A run action is named from its snapshot (`snapshotTargetTitle`). `actionTitleSnapshot` is what every COMPLETED/FAILED write stores (`mediaItemTitle`/`mediaItemParentTitle`: a series action keeps its show, parent null; `mediaItemSeasonNumber`/`mediaItemEpisodeNumber` for a one-episode action only). The scheduled executor stores the members it actually acted on.
- **All Episodes grid** heads each card `"<Show> SxxExx"`, lists by show then SxxExx (`sortBy=parentTitle`), with the episode title as the extra line (`episodeTitle`); a season's grid uses `SEASON_EPISODE_TOGGLES`.
- **Playback sessions** carry `seasonNumber`/`episodeNumber` (episodes only); `formatSessionMediaTitle` names an episode from `grandparentTitle` — never `parentTitle` (the season there).
