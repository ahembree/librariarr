## Prerequisites

- Docker and Docker Compose
- Node.js 22.13+
- [pnpm](https://pnpm.io/) 12 (`npm install -g pnpm`)

## Development Setup

Librariarr uses Docker Compose for development to provide a PostgreSQL database and hot-reloading.

<Steps>

1. **Clone the repository**

   ```bash
   git clone https://github.com/ahembree/librariarr.git
   cd librariarr
   ```

2. **Create a `.env` file**

   Copy the example and fill in the required values:

   ```bash
   cp .env.example .env
   ```

3. **Start the dev environment**

   ```bash
   pnpm docker:dev
   ```

   This builds the dev container, starts PostgreSQL, runs migrations, and starts the Next.js dev server with Turbopack hot-reloading.

4. **Open the app**

   Navigate to `http://localhost:3000`

</Steps>

## Development Commands

### Docker

| Command | Description |
|-|-|
| `pnpm docker:dev` | Start dev environment (foreground) |
| `pnpm docker:dev:detach` | Start dev environment (background) |
| `pnpm docker:dev:down` | Stop dev environment |
| `pnpm docker:dev:rebuild` | Rebuild containers from scratch |
| `pnpm docker:dev:clean` | Stop containers and delete DB volume |
| `pnpm docker:dev:logs` | Tail dev container logs |

### Database

| Command | Description |
|-|-|
| `pnpm docker:dev:db:push` | Push schema changes (fast iteration, no migration files) |
| `pnpm docker:dev:db:migrate` | Run Prisma migrations |
| `pnpm docker:dev:db:studio` | Open Prisma Studio (DB browser) |
| `pnpm docker:dev:db:reset` | Reset DB completely |

### Mock Data

Populate the database with fictional media data for testing or taking screenshots without exposing personal data.

| Command | Description |
|-|-|
| `pnpm docker:dev:seed` | Seed the dev database with mock data |

<Aside>
  The seed script creates a demo user with username `demo` and password `demo`. It also creates 3 media servers (Plex, Jellyfin, Emby) with overlapping libraries to demonstrate multi-server dedup. The script is idempotent — running it again replaces the previous seed data.
</Aside>

### Build & Lint

| Command | Description |
|-|-|
| `pnpm build` | Next.js production build |
| `pnpm lint` | ESLint |
| `pnpm exec prisma generate` | Regenerate Prisma client (needed after schema changes when DB isn't available) |

## Testing

Tests use **Vitest** with a real PostgreSQL test database (`librariarr_test`), auto-created by the global setup.

<Aside>
  The Docker dev database must be running for integration tests. Start it with `pnpm docker:dev` or `pnpm docker:dev:detach` before running tests.
</Aside>

### Test Commands

| Command | Description |
|-|-|
| `pnpm test` | Run full test suite |
| `pnpm test:watch` | Watch mode |
| `pnpm test:unit` | Unit tests only (no DB needed) |
| `pnpm test:integration` | Integration tests only (requires DB) |
| `pnpm test:coverage` | Run with coverage report |
| `pnpm exec vitest run tests/path/to/file.test.ts` | Run a single test file |

### Test Structure

- **`tests/unit/`** — Pure logic tests (rules engine, filters, sync detection, formatting, caching, validation schemas)
- **`tests/unit/hooks/`** — React hook tests, run under `happy-dom` (`// @vitest-environment happy-dom` at the top of each file) with `renderHook` from `@testing-library/react`
- **`tests/integration/`** — API route handler tests against a real database with mocked external services

### Browser end-to-end tests

Real-browser tests live in `e2e/` and run with Playwright, separately from Vitest.

| Command | Description |
|-|-|
| `pnpm e2e:docker` | Build the production image and run the whole suite in Docker (Postgres, the app and the official Playwright image, browsers included) |
| `pnpm e2e:docker:down` | Remove the e2e containers and their database volume |
| `pnpm e2e:install` | Download Chromium for running on the host (needs access to `cdn.playwright.dev`) |
| `pnpm e2e` | Run the suite on the host, against the app `pnpm build` produced (run it first) |
| `pnpm e2e:ui` | Playwright's interactive UI mode |
| `pnpm e2e:report` | Open the last HTML report |

The Playwright image's tag is never written by hand: both Docker scripts set `PLAYWRIGHT_VERSION` from the `@playwright/test` version in `pnpm-lock.yaml` (`scripts/playwright-version.mjs`), because the image's browsers only work with that exact library version. A bare `docker compose -f docker-compose.e2e.yml up` without it refuses to start.

## Documentation site

The documentation (this site) is an Astro + Starlight project in `docs/`, with its own `package.json` and lockfile.

| Command | Description |
|-|-|
| `pnpm docs:dev` | Start the docs dev server (`http://localhost:4321`) |
| `pnpm docs:build` | Production build |
| `pnpm docs:preview` | Preview the built site |

Both `dev` and `build` first validate the rule sets on the [rule set library](/docs/guides/rule-set-library/) page and generate the API reference's OpenAPI document from the app's source.

## Git Conventions

- **Pre-commit hook**: Runs `pnpm exec eslint --quiet` via Husky
- **Commit format**: [Conventional Commits](https://www.conventionalcommits.org/) enforced by commitlint
  - `feat: add new feature`
  - `fix(auth): handle expired tokens`
  - `docs: update installation guide`
  - `refactor: simplify rule evaluation`

## Project Structure

```
src/
├── app/                    # Next.js App Router
│   ├── (authenticated)/    # Protected pages (auth enforced by layout)
│   ├── api/                # API routes
│   ├── login/              # Login page
│   └── onboarding/         # First-time setup
├── components/
│   └── ui/                 # shadcn/ui primitives
├── hooks/                  # Custom React hooks
└── lib/
    ├── auth/               # Session management
    ├── arr/                # Sonarr/Radarr/Lidarr clients
    ├── backup/             # Backup & restore service
    ├── cache/              # In-memory cache
    ├── dedup/              # Multi-server deduplication
    ├── filters/            # Media filter utilities
    ├── jobs/               # Graphile Worker background job queue + scheduler
    ├── plex/               # Plex OAuth and API client
    ├── rules/              # Lifecycle rule engine
    ├── sync/               # Media sync engine
    └── validation.ts       # Zod schemas for API validation
```
