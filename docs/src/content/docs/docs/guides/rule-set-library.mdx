Every rule set on this page is the JSON the rule editor's **Export** button
produces, ready to paste into **Import**. Each one ships with its action
**configured but turned off**, so importing never arms anything: you preview
the matches, pick your Radarr or Sonarr instance, and switch the action on
when you are happy with the list.

The JSON sits folded under each rule set — open **JSON — …**, then use the
copy button in the top-right corner of the block. Every block is checked
against the app's own field, operator and action registries when the docs
are built, so what is published is what the editor accepts.

## Importing a rule set

<Steps>

1. Go to **Lifecycle → Rules** and open the tab that matches the rule set's
   `type` — **Movies** for `MOVIE`, **Series** for `SERIES`. The import is
   refused on the wrong tab.

2. Click **Import** (beside **Save** in the rule editor), paste the JSON, and
   click **Import** again. The editor fills in with the rules, action and
   settings.

3. On the **Actions** tab choose your *arr instance. A rule set whose action
   is **Change Quality Profile** also needs a profile picked here — profile
   ids belong to one instance, so they are never part of an export.

4. **Preview** the matches and read the list. Adjust any threshold that does
   not fit your library; the values below are starting points, not
   recommendations for every household.

5. Turn the action on if you want it, set the delay, and **Save**. A rule
   set with Discord notifications enabled only posts once a
   [webhook](/docs/features/notifications/) is configured.

</Steps>

What an export does **not** carry, because it is specific to one install:
the *arr instance and quality profile, which servers the rule set targets
(it imports targeting every server), and the collection's identity (a rule
set with collection settings is matched to an existing collection by name on
save, or creates one).

<Aside type="tip">
  **Export** on any of your own rule sets gives you the same JSON. It is how
  to back a rule set up, move it to another install, or share it.
</Aside>

## Unwatched movies

Movies added at least six months ago that nobody has played in a year, or
ever, and that are not on your Plex watchlist. Removed from Radarr with
their files and an import exclusion, after a week on the Pending page. This
is the rule set the
[delete unwatched media](/docs/guides/delete-unwatched-media/) guide builds.

**Needs:** Radarr, and play history established on every targeted server
(see [Play history](/docs/guides/delete-unwatched-media/#before-you-start)).

<details>
<summary>JSON — Unwatched movies</summary>

```json
{
  "version": 1,
  "type": "MOVIE",
  "name": "Unwatched movies",
  "rules": [
    {
      "id": "g1",
      "condition": "AND",
      "rules": [
        {
          "id": "r1",
          "field": "addedAt",
          "operator": "notInLastDays",
          "value": "180",
          "condition": "AND"
        },
        {
          "id": "r2",
          "field": "isWatchlisted",
          "operator": "equals",
          "value": "false",
          "condition": "AND"
        }
      ],
      "groups": [
        {
          "id": "g2",
          "condition": "AND",
          "rules": [
            {
              "id": "r3",
              "field": "playCount",
              "operator": "equals",
              "value": "0",
              "condition": "AND"
            },
            {
              "id": "r4",
              "field": "lastPlayedAt",
              "operator": "notInLastDays",
              "value": "365",
              "condition": "OR"
            }
          ],
          "groups": []
        }
      ]
    }
  ],
  "enabled": true,
  "actionEnabled": false,
  "actionType": "DELETE_RADARR",
  "actionDelayDays": 7,
  "addImportExclusion": true,
  "searchAfterAction": false,
  "addArrTags": [],
  "removeArrTags": [],
  "collectionEnabled": false,
  "collectionName": null,
  "collectionSortName": null,
  "collectionHomeScreen": false,
  "collectionRecommended": false,
  "collectionSort": "ALPHABETICAL",
  "discordNotifyOnAction": true,
  "discordNotifyOnMatch": false,
  "stickyMatches": false
}
```

</details>

`lastPlayedAt` **More Than X Days Ago** matches only items that have a last
played date, so `playCount equals 0` is ORed in for titles never played at
all. On Jellyfin and Emby `isWatchlisted` is never set, so that condition
simply matches every item there.

## Low-quality movies to replace

Movies whose file is standard definition, still monitored in Radarr, get a
**Search for New Copy**: Radarr looks for a release and replaces the file
only when its quality profile allows the upgrade. Nothing is deleted.

**Needs:** Radarr. See [replacing low-quality files](/docs/guides/replace-low-quality-files/)
for the quality-profile and delete-and-re-grab variants.

<details>
<summary>JSON — Low-quality movies to replace</summary>

```json
{
  "version": 1,
  "type": "MOVIE",
  "name": "Low-quality movies to replace",
  "rules": [
    {
      "id": "g1",
      "condition": "AND",
      "rules": [
        {
          "id": "r1",
          "field": "resolution",
          "operator": "contains",
          "value": "SD|480P",
          "condition": "AND"
        },
        {
          "id": "r2",
          "field": "arrMonitored",
          "operator": "equals",
          "value": "true",
          "condition": "AND"
        }
      ],
      "groups": []
    }
  ],
  "enabled": true,
  "actionEnabled": false,
  "actionType": "SEARCH_RADARR",
  "actionDelayDays": 1,
  "addImportExclusion": false,
  "searchAfterAction": false,
  "addArrTags": [],
  "removeArrTags": [],
  "collectionEnabled": false,
  "collectionName": null,
```

## Downgrade watched movies: change the profile

The first half of a downgrade. Movies someone has watched, that nobody has
played again in a month and that are not on the watchlist, are moved to a
lower Radarr quality profile — one that tops out at 1080p or 720p, say,
while new releases keep arriving in 4K. Pick that profile on the **Actions**
tab after importing; a movie already on it is skipped.

A profile change on its own never shrinks anything: Radarr only ever
replaces a file with one its profile ranks *higher*, so the 4K file stays
until the next rule set removes it. **Search for upgrade after profile
change** is left off for the same reason.

**Needs:** Radarr with a lower profile set up, established play history.

<details>
<summary>JSON — Downgrade watched movies (profile)</summary>

```json
{
  "version": 1,
  "type": "MOVIE",
  "name": "Downgrade watched movies (profile)",
  "rules": [
    {
      "id": "g1",
      "condition": "AND",
      "rules": [
        {
          "id": "r1",
          "field": "playCount",
          "operator": "greaterThanOrEqual",
          "value": "1",
          "condition": "AND"
        },
        {
          "id": "r2",
          "field": "lastPlayedAt",
          "operator": "notInLastDays",
          "value": "30",
          "condition": "AND"
        },
        {
          "id": "r3",
          "field": "isWatchlisted",
          "operator": "equals",
          "value": "false",
          "condition": "AND"
        }
      ],
      "groups": []
    }
  ],
  "enabled": true,
  "actionEnabled": false,
  "actionType": "CHANGE_QUALITY_PROFILE_RADARR",
  "actionDelayDays": 7,
  "addImportExclusion": false,
  "searchAfterAction": false,
  "addArrTags": [],
  "removeArrTags": [],
```

## Downgrade watched movies: replace the file

The second half. Movies already on the lower profile whose file is still
4K, and that have been played, get **Monitor & Delete Files** with
**Search after**: Radarr deletes the file and immediately searches for a
release the lower profile allows. Change `Archive` to the name of your
profile — with an instance selected, the rule builder lists its profiles
under **Quality Profile** — and widen `4K` to `4K|1080P` if the lower
profile stops at 720p.

Run the two together: the first moves a movie onto the profile, this one
replaces its file on a later cycle. Once the smaller file is in, the movie
no longer matches, and the same action is never repeated on an item.

**Needs:** Radarr with a recycle bin — without one the delete is immediate
— and established play history.

<details>
<summary>JSON — Downgrade watched movies (file)</summary>

```json
{
  "version": 1,
  "type": "MOVIE",
  "name": "Downgrade watched movies (file)",
  "rules": [
    {
      "id": "g1",
      "condition": "AND",
      "rules": [
        {
          "id": "r1",
          "field": "arrQualityProfile",
          "operator": "contains",
          "value": "Archive",
          "condition": "AND"
        },
        {
          "id": "r2",
          "field": "resolution",
          "operator": "contains",
          "value": "4K",
          "condition": "AND"
        },
        {
          "id": "r3",
          "field": "playCount",
          "operator": "greaterThanOrEqual",
          "value": "1",
          "condition": "AND"
        }
      ],
      "groups": []
    }
  ],
  "enabled": true,
  "actionEnabled": false,
  "actionType": "MONITOR_DELETE_FILES_RADARR",
  "actionDelayDays": 3,
  "addImportExclusion": false,
  "searchAfterAction": true,
  "addArrTags": [],
  "removeArrTags": [],
  "collectionEnabled": false,
  "collectionName": null,
  "collectionSortName": null,
  "collectionHomeScreen": false,
  "collectionRecommended": false,
  "collectionSort": "ALPHABETICAL",
  "discordNotifyOnAction": true,
  "discordNotifyOnMatch": false,
  "stickyMatches": false
}
```

</details>

<Aside type="caution">
  If Radarr's search finds no release the lower profile accepts, the movie
  is left with no file. Keep the profile's allowed qualities broad enough
  that something is always available, and preview the matches first.
</Aside>

For shows, build the same pair on the **Series** tab with **Series Scope**
on: `watchedEpisodePercentage` **greater than or equal** `100` and
`seriesLastPlayedAt` **More Than X Days Ago** `30` select fully watched
shows for **Change Quality Profile** (Sonarr), and **Monitor & Delete Files**
on the lower profile replaces every episode file.

## Large unwatched files to review

Not a cleanup, a watch list: movies over 20 GB that nobody has played in the
three months since they arrived. The action is **Do Nothing**, so the rule
set only collects matches, and the Discord match notification tells you when
the list changes. Useful as a first rule set while you get a feel for what
matching looks like on your library.

**Needs:** nothing beyond a synced server (play history for `playCount`).

```json

          "id": "r1",
          "field": "fileSize",
          "operator": "greaterThan",
          "value": "20000",
```
