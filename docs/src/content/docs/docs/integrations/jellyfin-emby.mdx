Librariarr supports Jellyfin and Emby as media server backends alongside Plex.

## Setup

<Steps>

1. Go to **Settings → Media Servers**
2. Click **Add Server** and choose **Jellyfin** or **Emby**
3. Enter connection details:
   - **URL**: Your server's base URL, including `http://` or `https://` (e.g., `http://192.168.1.100:8096`)
   - **API Key**: An API key from your server
   - **Skip TLS verification**: Enable for self-signed certificates
4. Click **Test** — **Add Server** stays disabled until the test passes
5. Click **Add Server**, then select which libraries to sync

</Steps>

The API key is an admin key: it can delete media and shut the server down. So
changing a server's URL, or turning on **Skip TLS Verification**, without
entering a new key needs a sign-in from the last 15 minutes — the saved key
would go to the new address, or to whoever answers there unverified. If it has
been longer, Librariarr asks you to confirm it's you and then carries on.

### Getting an API Key

#### Jellyfin

1. Open **Jellyfin Dashboard**
2. Navigate to **API Keys** (under Advanced)
3. Click **Add** and name it "Librariarr"
4. Copy the generated key

#### Emby

1. Open **Emby Server Dashboard**
2. Navigate to **API Keys**
3. Create a new key named "Librariarr"
4. Copy the generated key

## Synced Data

The same metadata is synced as with Plex:

- Core metadata (title, year, ratings, genres, etc.)
- Video, audio, and subtitle stream details
- File information and external IDs
- Play counts and history, from every user's played items (or from [Tracearr](/docs/integrations/tracearr/), if you map the server to it)
- Favorites — an item marked as a favorite counts as **watchlisted** in Librariarr

## Feature Parity Notes

Most Librariarr features work identically with Jellyfin and Emby. However, some features have differences:

| Feature | Plex | Jellyfin/Emby |
|---------|------|---------------|
| OAuth login | Yes | No (API key only) |
| Server discovery | Automatic | Manual URL entry |
| Active stream monitoring | Yes | Yes |
| Maintenance mode | Yes | Yes |
| Preroll support | Native (Plex Pass) | No — the Preroll Manager is Plex-only |
| Lifecycle collections | Yes | No — Plex-only |
| Transcode management | Yes | Yes |
| Real-time sync of added items | Yes | Yes — the item's library is resolved from its parent chain |

<Aside>
  Plex OAuth remains the primary authentication method for Librariarr itself. Even when using Jellyfin or Emby as your media server, you can use Plex OAuth to log in to Librariarr, or use local authentication as an alternative.
</Aside>

## Multi-Server Setup

You can connect multiple servers of any type simultaneously:

- Multiple Plex servers
- Plex + Jellyfin
- Plex + Emby
- Any combination

When the same media exists on multiple servers, Librariarr's [deduplication system](/docs/getting-started/connecting-a-server/#multi-server-deduplication) handles it automatically.

## Limitations

- No auto-discovery for Jellyfin/Emby — you must enter the URL manually
- Some metadata fields may differ slightly between server types due to different APIs
- The [Preroll Manager](/docs/features/preroll-manager/) and lifecycle-managed collections only work with Plex servers
- Only libraries whose content type is **Movies**, **Shows** or **Music** are synced. A *mixed content* library has no content type and is skipped; if you change an existing library's content type to mixed, it is removed from Librariarr on the next full sync like any library the server no longer reports as one of those three
- Watch history comes from each user's played-items list, so it carries play counts and last-played dates but not the per-play timestamps Plex provides. If a user's list cannot be fetched during a sync, the previous history is kept rather than partially replaced; a user the API key cannot read is skipped and logged
