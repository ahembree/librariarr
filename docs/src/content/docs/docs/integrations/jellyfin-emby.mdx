Librariarr supports Jellyfin and Emby as media server backends alongside Plex.

## Setup

<Steps>

1. Go to **Settings → Servers**
2. Click **Add Server**
3. Select **Jellyfin** or **Emby** as the server type
4. Enter connection details:
   - **URL**: Your server's base URL (e.g., `http://192.168.1.100:8096`)
   - **Access Token**: An API key from your server
   - **Skip TLS Verification**: Enable for self-signed certificates
5. Click **Test Connection**
6. Select which libraries to sync
7. Save

</Steps>

### Getting an API Key

#### Jellyfin

1. Open **Jellyfin Dashboard**
2. Navigate to **API Keys** (under Advanced)
3. Click **Add** and name it "Librariarr"
4. Copy the generated key

#### Emby

1. Open **Emby Server Dashboard**
2. Navigate to **API Keys**
3. Create a new key named "Librariarr"
4. Copy the generated key

## Synced Data

The same metadata is synced as with Plex:

- Core metadata (title, year, ratings, genres, etc.)
- Video, audio, and subtitle stream details
- File information and external IDs
- Play counts and history

## Feature Parity Notes

Most Librariarr features work identically with Jellyfin and Emby. However, some features have differences:

| Feature | Plex | Jellyfin/Emby |
|---------|------|---------------|
| OAuth login | Yes | No (API key only) |
| Server discovery | Automatic | Manual URL entry |
| Active stream monitoring | Yes | Yes |
| Maintenance mode | Yes | Yes |
| Preroll support | Native (Plex Pass) | Varies by version/plugins |
| Transcode management | Yes | Yes |
| Real-time sync of added items | Yes | Yes — the item's library is resolved from its parent chain |

<Aside>
  Plex OAuth remains the primary authentication method for Librariarr itself. Even when using Jellyfin or Emby as your media server, you can use Plex OAuth to log in to Librariarr, or use local authentication as an alternative.
</Aside>

## Multi-Server Setup

You can connect multiple servers of any type simultaneously:

- Multiple Plex servers
- Plex + Jellyfin
- Plex + Emby
- Any combination

When the same media exists on multiple servers, Librariarr's [deduplication system](/docs/getting-started/connecting-a-server/#multi-server-deduplication) handles it automatically.

## Limitations

- No auto-discovery for Jellyfin/Emby — you must enter the URL manually
- Some metadata fields may differ slightly between server types due to different APIs
- Preroll functionality depends on server-side support, which varies for Jellyfin and Emby
- Only libraries whose content type is **Movies**, **Shows** or **Music** are synced. A *mixed content* library has no content type and is skipped; if you change an existing library's content type to mixed, it is removed from Librariarr on the next full sync like any library the server no longer reports as one of those three
- Watch history comes from each user's played-items list, so it carries play counts and last-played dates but not the per-play timestamps Plex provides. If the server cannot be read during a sync (unreachable, timing out, or answering with something that is not a played-items list), the previous history is kept rather than partially replaced. If only one user's list cannot be read completely — the API key is refused for that user, or the list comes back empty or far shorter than the count the server reports (for example when parental controls hide that user's items) — that user's previously stored plays are kept as their last known record and the user is logged, while everyone else's history is refreshed as usual. A user whose list comes back incomplete and who has no plays stored at all keeps lifecycle rules that use play history paused for that server while its watch history is being established — on its first sync, and again after a purge, a restore, a change of watch-history source, a library's first sync, or the removal from the server of a library that held items — because nothing then records what that user watched. **Refresh** on the History page does not lift that pause: make the user's played items readable in Jellyfin or Emby (their library access and parental controls), or remove the user there. A refused user never pauses the rules. If no user's list can be read at all, or the server ignores the paging of the list (for example a proxy that always returns the first page), the sync fails and the stored history is kept
- When two libraries cover the same folder, the item is stored once per library and each play counts towards both copies, so both read as watched to your rules. Lists of plays — the History page, a show's play history — and the watch analytics show such a play once. With three or more such libraries, deleting the copy that holds a play's main record lists the play once per remaining copy until the next watch-history sync rewrites it (for a user whose list cannot be read in full, until it can)
