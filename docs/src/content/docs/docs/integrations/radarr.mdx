Radarr integration enables lifecycle actions on movies managed by Radarr.

## Setup

<Steps>

1. Go to **Settings → Integrations**
2. Under the **Radarr** section, click **Add Instance**
3. Enter:
   - **Name**: A label for this instance (e.g., "Main Radarr")
   - **URL**: Radarr's base URL (e.g., `http://192.168.1.100:7878`) — the address Librariarr uses to reach Radarr
   - **External URL** (optional): The address your browser uses for Radarr, starting with `http://` or `https://`. Used for "open in Radarr" links; falls back to **URL** when empty
   - **API Key**: Found in Radarr → Settings → General → API Key
4. Click **Test** to verify — **Save** stays disabled until the test passes
5. Save

</Steps>

You can add multiple Radarr instances. A rule set reads its Radarr criteria from the instance its action is linked to (see [lifecycle rules](/docs/features/lifecycle-rules/)).

Deleting an instance cancels the pending lifecycle actions bound to it and detaches it from every rule set that used it; those rule sets' actions are turned off until you pick another instance.

## How Matching Works

Librariarr matches movies to Radarr using **TMDB IDs**:

1. During media sync, external IDs (including TMDB) are fetched from your media server
2. When lifecycle rules need Radarr data, Librariarr queries Radarr by TMDB ID
3. There is no title fallback: a movie without a TMDB ID is never found in Radarr, and an action on it fails. Before acting, Librariarr also checks that the Radarr movie's title and year match, so a wrong ID never acts on a different film

<Aside>
  Ensure your media server's metadata agent populates TMDB IDs for movies. This is the default behavior for most agents.
</Aside>

## Available Operations

Once connected, these operations are available via [lifecycle rules](/docs/features/lifecycle-rules/):

| Operation | Description |
|-----------|-------------|
| **Delete from Radarr** | Remove the movie from Radarr **and delete its files from disk** |
| **Unmonitor & Delete Files** | Unmonitor the movie and delete its file |
| **Monitor & Delete Files** | Make sure the movie is monitored, then delete its file so Radarr grabs a new copy |
| **Delete Files Only** | Delete the movie's file without changing monitoring |
| **Unmonitor Only** | Stop Radarr from monitoring the movie |
| **Change Quality Profile** | Move the movie to another quality profile (skipped if it is already on it) |
| **Search for New Copy** | Trigger a Radarr search, changing nothing else |
| **Do Nothing** | Only track the match (and apply tag changes, if configured) |

Every action can also **add and remove Radarr tags**, applied before the main action. **Delete from Radarr** can also **add an import list exclusion** so import lists don't add it back, and the file-delete and quality-profile actions can **search after** the change. When a destructive action is linked to an instance with no recycle bin configured, the rule editor warns you before saving. See [Available Actions](/docs/features/lifecycle-rules/#available-actions).

## Data from Radarr

The following Radarr metadata is available for lifecycle rule conditions:

- **Found in Arr**, **Monitored**, **Tag**, **Quality Profile**, **Quality Name**, **Quality Cutoff Met**, **Custom Format Score**, **Status**
- **IMDB Rating**, **TMDB Rating**, **RT Critic Rating**, **Original Language**, **Runtime**, **Size on Disk**, **Path**
- **Release Date**, **In Cinemas Date**, **Date Added**, **Download Date**

## Security

- API keys are stored securely in the database and never exposed to the frontend
- Connection testing uses server-side endpoints with stored credentials
- API responses are sanitized to mask sensitive fields

## Limitations

- Matching requires TMDB IDs — movies without one are not found in Radarr
- Lifecycle actions call Radarr's API in real time. Requests time out after 15 seconds; reads are retried up to 3 times, writes are not. If Radarr is unreachable during a scheduled run, its remaining actions stay pending for the next run; a manual **Execute** fails them
- Bulk delete operations call the API once per movie — very large batches may take time
